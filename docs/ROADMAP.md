# 路线图：让 Charlie 像真人一样和你对话（2026-09-25 更新）

目标 = 那个 B 站视频（VoxEMW）的效果：一个人坐在屏幕里，看着你，你说话他听，
他用自己的声音、自己的观点回你，嘴型跟声音对得上，你打断他他立刻停。
约束：**脸必须本地跑**（M5 Max，不租卡）；大脑可以上云（DeepSeek）。

---

## 一、现在的样子（全部本机实测）

```
麦克风 → ① 判停 → ② 转文字 → ③ 大脑 → ④ 合成语音 → ⑤ 数字人 → 浏览器
         Silero    Qwen3-ASR   DeepSeek   Qwen3-TTS    MuseTalk       canvas 按 pts 显示
         +SmartTurn (MLX,GPU)  (云端中转)  克隆音色(GPU)  UNet→ANE      音频扣到首帧再开播
                                                       半脸VAE→GPU
                                                       贴回→CPU
```

| 积木 | 状态 | 实测 |
|---|---|---|
| ①②④ 语音链 | ✅ | 说完到出声 ~3.0s（DeepSeek 中转固定 2.2s；本地 Qwen 时 1.2s） |
| ③ 大脑 | ✅ DeepSeek | 人设稳、内容比本地 Qwen 强；`thinking` 必须显式关掉，否则正文为空 |
| ⑤ 数字人 | ✅ **真·按音频现算的嘴** | 20fps 目标；独跑 21.5fps，对话中 15–17fps（自适应降帧兜底） |
| 打断 | ✅ | 音频清队列，画面瞬切待机循环 |

⑤ 是今天的变化：不再是两段录像循环。每一帧的嘴由那一刻的音频算出来（MuseTalk，
不需要针对他训练）。底子是他本人的影像（眨眼、头动、肩膀都是真的）。

## 一·五、2026-09-25 下午的三处改动（对应你的三条反馈）

| 反馈 | 原因 | 现在 |
|---|---|---|
| 他不看我 | 底子是街头四分之三侧脸；竖幅底子被 `object-fit:cover` 裁掉脸 | 服务端固定**人脸中心 4:3 取景**；底子换成 1080p 采访里唯一正对镜头的 2.4s（`web/media/base_frontal.mp4`，往返循环）；抠像换成演播室深蓝背景 |
| 他不说话 | 嘴被裁掉；待机视频与生成帧是两套画面 | **待机帧也由服务端推**（同一取景、同一条头部运动轨道），说话时切成生成帧，游标连续 |
| 嘴动时没字 | 整段说完才发文本 | 每段 TTS 文字带音频 pts 先发，浏览器按音频时钟逐句显示 |

另外：贴回遮罩从"整个下半张脸"改成"按关键点的嘴周椭圆"——脸颊、下颌、话筒保留原片清晰度（对比图 mask_ab.jpg）。

底子素材扫描（8 个 agent 逐帧看完 58 分钟 1080p）：**整段只有 2295.6–2297.6 这 2 秒真正正对镜头**，其余 ≥3s 的都是户外、看提问者或闭眼。
所以"看着你"的上限仍受素材限制——**给我一段他坐在演播室/播客、正对固定机位、无手持话筒、身后无人的 5–15 秒影像**，效果会再上一个台阶。

## 一·六、2026-09-26：底子换成 Fox 远程连线机位

YouTube/Rumble 从本机下不了（机器人验证 / 403），**foxnews.com 的视频页可以**（720p）。他上 Fox 节目是远程连线分屏：
正对镜头、头肩构图、嘴前无遮挡、字幕在下巴以下。5 条节目、agent 逐张看接触表后选定
`web/media/base_fox_listen.mp4`（Jesse Watters Primetime，454–466s，他在倾听、闭嘴、头几乎不动——MuseTalk 最理想的参考状态），
`pre_crop` 只取右半屏并去掉字幕条。端到端：214 帧 / 14.6s 音频全程覆盖，落后 ≤0.3s，有效 14.7 fps。
其它可用段落记在记忆文件 footage-fox-remote-guest。

## 二、脸这条路是怎么走通的

1. 九月的结论"MuseTalk 30.7 fps 可用"是**爆发态**数字：GPU 持续负载 1 秒后降到 1/3，
   真实只有 14.5 fps。所以全 GPU 方案不成立。
2. 把 UNet 搬到**神经引擎**（Core ML，Apple 的 ANE 友好结构）：29ms/帧，与 GPU 物理隔离。
3. GPU 只剩 Whisper 编码和**只解码下半张脸**的 VAE（16–29ms）；CPU 贴回 2ms。三级流水线。
4. 两个坑：coremltools 的 predict 持有 GIL → Core ML 必须在子进程；ANE 对父进程 CPU 活动敏感
   （29→40ms）→ 目标帧率定 20，来不及时自动隔帧算。
5. 浏览器侧：每回合先扣住音频，等第一帧到了一起开播；帧按 pts 对齐音频时钟；帧晚到就保持上一帧。

细节与数字：docs/musetalk-measured.md 末尾"2026-09-25 追加"。

## 三、接下来按收益排序

### 1. 底子素材（收益最大，你来提供）

现在的底子是街头辩论 480p 的 1.8 秒待机片段（四分之三侧脸、话筒挡嘴）。MuseTalk 重绘
下半张脸，在这种底子上明显发糊、话筒会被抹掉。**换一段高清、正对镜头、无遮挡、
安静倾听 5–15 秒的影像**，效果会是另一个档次——不需要训练，换文件重启即可
（`configs/assistant.json` → `face.base_video`）。

### 2. 嘴部遮罩收紧（半天）

现在贴回整个下半张脸。改成按关键点只贴嘴周区域，脸颊、下巴、话筒保持原片清晰度。

### 3. 帧率余量（1 天）

目前对话中 15–17 fps，靠自适应降帧兜底。可做：
- 6-bit 调色板量化 UNet（ANE 原生支持，减少权重带宽；k-means 压缩很慢，正在跑）
- 渲染线程与 TTS 错峰：TTS 合成完一段前不抢 GPU 解码
- 把贴回/JPEG 移到第二个子进程，减少父进程 CPU 活动对 ANE 的干扰

### 4. 待机↔说话的接缝（半天）

说话结束回到待机视频时有一次画面跳变（底子循环位置不同步）。回合结束时把底子游标
发给浏览器，让待机视频 seek 到同一帧。

### 5. 首音延迟（取决于大脑）

DeepSeek 中转固定 2.2s 首字。换官方 api.deepseek.com 或更快的中转可回到 ~1.5s；
本地 Qwen 是 0.7s 但会和渲染抢 GPU。

## 四、诚实的预期

现在打开页面看到的是：他本人的影像，嘴按你听到的每个字实时重绘，20fps 上下，
你插话他立刻停。缺陷：嘴部区域比原片软、话筒消失、说话结束回待机有一跳。
第 1、2 项做完，视频通话尺寸下第一眼像他，经不起放大细看——这是 MuseTalk 256 分辨率的天花板。
再往上就是 ROADMAP.v1.md 里那条"针对他训练专属模型"的路。
