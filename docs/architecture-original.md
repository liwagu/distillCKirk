# 架构决策书 · distillCKirk

目标：M5 Max / 128GB 上全本地运行的实时英语辩论数字人。
所有性能数字均为**本机实测**（见 measured-hardware.md 与 corpus/raw/）。

---

## 1. 原方案六块积木的裁决

| # | 你的原方案 | 裁决 | 换成 | 依据 |
|---|---|---|---|---|
| 1 | silero-vad-v5 | **KEEP** | 改用官方 `snakers4/silero-vad` | 实测 0.139ms/32ms 帧 = 0.43% 单核。官方 wrapper 已处理 64-sample 上下文，runanywhere 镜像没有 |
| 2 | Qwen3-ASR-1.7B | **KEEP，但降级默认档** | 默认 0.6B，1.7B 可选 | 走 `mlx-qwen3-asr`（纯 MLX，无 torch）。1.7B 空闲时 4s 句 270ms，**有 LLM 争抢时 489ms，8.9s 长句 p90 飙到 2060ms** |
| 3 | DeepSeek v4 | **SWAP** | 本地 MoE（见 §3） | v4 无开放权重可本地跑。你要全本地就必须换 |
| 4 | VoxCPM2 | **DROP** | `Qwen3-TTS-12Hz-1.7B-Base-8bit` | 决定性：mlx-audio 的 VoxCPM2 移植**没有分块流式**，一次性 yield，TTFA=整句生成时间 2.9–11.2s。且英语 WER 1.84 输给 Qwen3-TTS 的 1.24 |
| 5 | 女娲 nuwa-skill | **KEEP** | 方法论采纳，模板需改造 | 见 §5 |
| 6 | SoulX-FlashHead | **DROP** | 分阶段，见 §4 | 实测算力比推算 ≈11 fps，达不到 25fps |

**净变化：换掉 2 块（TTS、数字人），换掉大脑来源，其余保留。**

---

## 2. 核心系统性风险：GPU 争抢

VoxEMW 从未遇到此问题——**他的大脑在云端**，本地 GPU 只跑 ASR+TTS+渲染。
你要全本地，就把最重的消费者搬进了同一块 Metal 设备。实测代价：

| | 空闲 | 有 LLM 级负载 | 劣化 |
|---|---|---|---|
| TTS TTFA | 0.13–0.20s | 0.31–0.42s | 2.2x |
| TTS RTF | 0.33–0.52 | **0.76–0.92** | 逼近 1.0 |
| ASR 3.9s 句 | 270ms | 489ms | 1.8x |
| ASR 8.9s 句 | 889ms | 1180ms (p90 2060) | 尾部炸裂 |

RTF 0.92 = 生成刚好追平播放，**长回复有断音风险**。缓解手段见 §6。

---

## 3. 延迟预算（实测推算）

用户停止说话 → 首个音节出声。以 4 秒发言为例：

| 阶段 | 全本地 | 说明 |
|---|---|---|
| VAD 静音 + SmartTurn 语义判停 | 200 ms | CPU，不受争抢影响（SmartTurn 实测 18ms） |
| ASR（争抢下 p50） | 490 ms | 0.6B 可压到 ~250ms |
| LLM 首句（前缀缓存命中） | ~300 ms | **待实测**，MoE ~70 tok/s 下 15 token ≈ 215ms + prefill |
| TTS TTFA（争抢下） | 360 ms | |
| **合计 p50** | **≈ 1.35 s** | 目标 2.0s，达标 |
| **p90** | **≈ 1.7 s** | 仍在硬顶 3.0s 内 |

结论：**全本地可行**。但余量集中消耗在 GPU 争抢上，LLM 首句延迟是唯一未实测项。

## 4. 数字人：分档，按实测推进

**SoulX-FlashHead 出局。** 4090 bf16 张量核 ≈165 TFLOPS，本机实测 20.0 TFLOPS，
比值 8.3x。作者实测 4090 上 0.27s 生成 0.96s 画面 → 本机 ≈2.2s，即 **11 fps**，
差 25fps 一倍以上。且这是乐观上界（SoulX 走 PyTorch MPS，效率低于 matmul 峰值）。

> 注：一个验证 agent 曾主张此结论不成立、SoulX 可达 23–40fps。它的依据是怀疑
> 原报告那个 19.9 TFLOPS 的估算值。但本机实测 bf16 = 20.0 TFLOPS，**独立证实了
> 该估算**。原结论成立，该反驳不成立。

档位规划：

- **Tier D（Phase 3 默认）**：预渲染待机/说话视频循环，按说话状态交叉淡化。0 GPU、0 延迟、零争抢风险。
- **Tier B（Phase 4 候选）**：MuseTalk-1.5 via `musetalk-mlx`。作者在**同型号 M5 Max 128GB** 上报 34fps。
  但该基准**不含** VAE encode、whisper encoder、paste-back 三段，真实吞吐必然更低——**上线前必须自己实测端到端**。
  且它会与 ASR/TTS/LLM 抢 GPU，需重新评估 §2 的预算。
- **Tier A**：本机无解，不再考虑。

无论哪档，VoxEMW 的渲染工程可**原样复用**：paced 喂入、攒段/生成/滴灌三段流水线、
25fps deadline 调度、flush 代际打断。见 `ref-VoxEMW/voxemw/avatar/soulx_server.py`。

## 5. 人设构建

数据源：`corpus/raw/ck-positions-gender.json`（26 条立场，全部带出处、分级可信度、
10 处记录空白显式标注）+ `ck-style-rhetoric.json`（辩论打法，**含 3 处需剔除的错误条目**）。

三条硬约束：

1. **只能主张有 cite-id 的立场。** 记录里没有的，回答"我得想想"，不许即兴发明政治主张。
2. **敌意和美化的失真同样致命。** 把他简化成"女人不该工作"是稻草人——他有明确的
   反例原话（立场 #11）；但只说他"重视家庭"又漏掉了避孕药、约会市场、强奸例外那些硬材料。
   两种失真都让辩论失去价值。
3. **回合计数状态不能放进 prompt。** 让步上限、难度调节这类计数器必须由 orchestrator
   持有——模型在 `chat_size: 30` 滚动窗口 + 打断重写下无法可靠自计回合数。

**最值得攻击的那条缝**（立场 #26）：2018–19 他的框架是"平等已实现，女性正在赢，
薪酬差距是伪命题"；2023–25 变成"女性职业化本身就是问题"。这两个框架互相矛盾——
前者说女性在现有安排下过得很好，后者说这个安排正在毁掉她们。这是他公开记录里
最实在的自相矛盾，也是你辩论时最该往里打的地方。

## 6. 施工阶段

每阶段独立可演示、可验证。**Phase 1 刻意不做音色克隆、不做数字人。**

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **P1** | VAD+SmartTurn → ASR → 本地 MoE → 默认音色 TTS，浏览器 WS 全双工，支持打断 | 能用英语连续辩论 10 轮，端到端 p50 < 2s，打断响应 < 300ms |
| **P2** | 人设注入 + 引用账本 + 护栏；音色克隆 | 立场可溯源；音色一致不漂移；AI 身份声明常驻 |
| **P3** | Tier D 视觉 | 说话/待机切换自然 |
| **P4** | 实测 MuseTalk-MLX 端到端；达标才上 Tier B | 含全部前后处理仍 ≥25fps，且不破坏 §3 预算 |

## 7. 必须预防的坑（来自参考仓库血泪注释 + 本次调研）

1. **音画漂移**：逐块 `sleep(间隔)` 累积 1.2–1.6%/分钟误差。必须用虚拟时刻表 `next_t += 间隔`。
2. **热词幻觉**：STT 注入 10 个热词会让模型把没说的话脑补成词表内容。上限 2–3 个，其余靠转写后确定性替换。
3. **权重静默丢失**：Qwen3-ASR 必须用 `-hf` 变体，非 `-hf` 在 transformers 5.x 下静默丢权重、不报错。
4. **localhost 走代理**：有全局代理时 websockets 会把 127.0.0.1 也走代理导致握手 EOF。必须设 `no_proxy=127.0.0.1,localhost,::1`。
5. **voice_control 是 VoxCPM2 专属**：qwen3 后端下会导致 `--qwen3_tts_ref_audio None`。克隆路径必须提供 `ref_wav` + `ref_text`。
6. **参考音选材**：用**坐着录的播客**，不要用集会/辩论棚。零样本克隆会连韵律和音区一起复制——拿对着人群喊话的素材，克隆出来说什么都在吼。
7. **上游 s2s 拥有回合触发权**：orchestrator 拿到转写时回复已在生成。任何"检索后再注入"的设计必须重新算延迟预算，不能当成零成本。
