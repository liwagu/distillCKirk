# 第二轮复核（Kimi 对抗性审查 + 自查）2026-09-10

## 确认成立的错误（我的）

### 1. 结论 1 与结论 6 自相矛盾 —— 论证错，结论对

我写「渲染器必须上 ANE，因为 TTS 在负载下 RTF 已 0.92、只剩 8% 余量」。
但 **0.92 只在 LLM 与 TTS 并发时出现**，而结论 6（整句生成后再开口）
恰恰禁止了这种并发。按我自己的设计，TTS 跑在说话阶段、GPU 上没有 LLM，
RTF 是 0.35，余量 65% 而非 8%。

且「再加 GPU 渲染器就越过 1.0」是无支撑的算术：MuseTalk 的 9–19x 劣化
是因为 MuseTalk 自己重（~800 GFLOP/帧），不能外推到 6.33 GFLOP/帧的小网。
**TTS × 小渲染器的并发我从未测过。**

修正后的正确论证：
- ANE 该选，理由是「说话阶段 TTS 与渲染器必然并发，而该并发未经测试；
  ANE 代价为零（占 ANE 3.7%），可无成本消灭这一整类风险」。
- **不是**「8% 余量」。那个数字在最终架构里根本不会出现。
- 推论：Metal 渲染器 + 时间分离**很可能也能工作**。ANE 是稳妥选择而非唯一可行解。

### 2. BT.1359 的 125ms 被我误用

我写「音频滞后画面 125ms 内不可察觉 → 免费买回 125ms 前瞻预算」。
**错。它只放宽音画对齐容差，不减少流水线延迟。**

每回合开头渲染第 0 帧仍需约 360–400ms 未来音频，这段音频要先由 TTS 生成
（RTF 0.35 下约 140ms），再叠加为避免「声音跑在嘴前」而主动延后的播出量。
**净增每回合首音 150–400ms，我的预算里没有这一项。**

修正：端到端 1.35s → **1.5–1.75s**。仍在 2s 内，但余量远比我说的小。

### 3. 「打断时一帧即停」是错的

模型逐帧无状态，但**窗口有状态**。打断瞬间最后约 9 帧（360ms）的未来音频
不存在了——要么用残缺上下文渲染出鬼影嘴型，要么冻结。
打断恰是最显眼的时刻，需要明确策略：**立即切预录待机循环**，不是「一帧即停」。

### 4. 打断目标前后不一致

任务目标写 <100ms，architecture.md 的 P1 验收写 <300ms。需统一。
考虑 CoreAudio 输出缓冲 + 已入队音频，100ms 很紧。

## 漏掉的积木（严重）

### 5. HuBERT 音频特征编码器完全不在架构里

`bench_ane.py` 的 `ASHAPE = (1,16,32,32)` 是 **hubert 模式**——
Ultralight 血统的 U-Net 吃的不是原始音频，是 HuBERT/wav2vec 提取的特征。
该编码器（~95M 参数，每音频 chunk 都要跑）在我的架构图、延迟预算、
显存预算里**均不存在**。放 Metal 就重新引入争抢，放 ANE 要再验证一轮。

**这不是细节，是一块缺失的积木。**

### 6. 回声消除（AEC）零提及

全双工 + 扬声器 → ASR 听到数字人自己的声音 → 自触发。
要么设计 AEC，要么显式规定戴耳机。

### 7. 针对本人微调是一整个工程阶段，不是一句话

FeatherTalk 要在他脸上重训：数据采集规范、训练时长、口型覆盖度失败模式，
全部无着落，Phase 划分里也没有这一阶段。

## 新的头号风险：LLM prefill

我标注「~300ms 待实测」，但低估了量级。

人设 prompt + 引用账本 + chat_size 30 滚动历史 ≈ 2–4k token。
5B 激活 MoE prefill 3k token ≈ 2×5.3e9×3000 = **31.8 TFLOP ÷ 20 TFLOPS ≈ 1.6s**。
预算直接爆炸。

依赖前缀缓存可以规避——但 **architecture.md 自己写了打断会重写历史，
每次打断缓存即失效，全量重 prefill 落在最不该慢的时刻。**

缓解：历史改为**只追加**（打断时追加 `[interrupted]` 标记而非重写前文），
保持前缀不变、缓存永远命中。这是设计层面的修复，必须写进规范。

另：「MoE 60–90 tok/s」是外推不是实测，与「全部实测非外推」的自我要求不符。
「40 token ≈ 570ms」的回复长度假设也太乐观——辩论回答 100+ token 是常态，
需要硬性长度控制机制。

## 独立印证：带宽维度

Kimi 指出争抢测试只做了算力型、没做带宽型（而真实 MoE 解码是带宽密集）。
我在收到该审查前已自行发现并补测（见 ane-verified.md 第二轮）：
ANE 在带宽型负载下 1.12x、CPU 打满下 1.53x（p99 14.17ms）。
**两条独立路径识别出同一缺口 → 该缺口确实存在，现已关闭。**
