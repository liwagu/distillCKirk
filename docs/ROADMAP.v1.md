# 完整路线图：让 Charlie 像真人一样和你对话

目标 = 那个 B 站视频（VoxEMW）的效果：一个人坐在屏幕里，看着你，你说话他听，
他用自己的声音、自己的观点回你，嘴型跟声音对得上，你打断他他立刻停。

---

## 一、那个 B 站视频到底是怎么做的

VoxEMW 的六块积木，全跑在一张 **RTX 4090（24GB 显存）** 上，只有大脑在云端：

```
麦克风 → ① 判停 → ② 转文字 → ③ 大脑 → ④ 合成语音 → ⑤ 数字人 → 浏览器
         Silero    Qwen3-ASR   DeepSeek   VoxCPM2     SoulX-FlashHead
         +SmartTurn            (API)      (克隆)      (音频驱动，实时)
```

作者的实测：说完到开口约 2–2.5 秒；⑤ 在 4090 上是 **3.5 倍实时**（0.27s 算出 0.96s 画面）。

## 二、我们现在有什么（全部本机实测过）

| 积木 | 状态 | 实测 |
|---|---|---|
| ① 判停 | ✅ 完成 | Silero + SmartTurn，CPU，85x 实时；带前置缓冲、900ms 兜底 |
| ② 转文字 | ✅ 完成 | Qwen3-ASR-1.7B（MLX），~180–300ms，逐字准确 |
| ③ 大脑 | ✅ 完成 | Qwen3-30B-A3B（本地 MoE），TTFT ~740ms，前缀缓存 99.7% |
| ④ 合成语音 | ✅ 完成 | Qwen3-TTS + **他本人的克隆音色**（播客切的 8 秒） |
| 人设 | ✅ 完成 | 26 条有出处的立场 + 15 种辩论打法 + 4 层守卫（正则/复读/词数/语义） |
| 全双工打断 | ✅ 完成 | 你开口他就停 |
| **⑤ 数字人** | ❌ **占位符** | 播放两段录像循环，**嘴型是假的** |

**①–④ 端到端：说完到出声 1.1–1.4 秒**，已经比 B 站视频的 2–2.5 秒快。
**声音这一半，我们已经做到了。差的是脸。**

## 三、脸为什么难——三条路的实测

问题只有一个：**这台 Mac 没有 4090。** 实测 bf16 算力 20 TFLOPS，4090 是 165，差 8 倍。

| 方案 | 原理 | 本机实测 | 结论 |
|---|---|---|---|
| SoulX-FlashHead（B 站视频用的） | 视频扩散，多步去噪 | 推算 ~11 fps | ❌ 差 25fps 一倍多 |
| MuseTalk | 单步潜空间修复 | **4.5 fps**（端到端） | ❌ 差 5.5 倍，且抢 GPU 会让 TTS 断音 |
| **ANE 专属小模型** | 训练一个只画嘴的小网络，跑在神经引擎 | **1.49 ms/帧**（GPU 打满时） | ✅ **余量 14 倍，唯一可行** |

第三条能行的原因：**神经引擎是独立于 GPU 的另一块芯片**。ASR/TTS/LLM 把 GPU 打满时它一毫秒都不慢。我用真实拓扑（随机权重）实测过，不是推算。

代价：它**必须针对他本人训练**——通用权重不存在。

## 四、从现在到目标：七步

### 第 1 步：素材 ← **当前卡在这里**

需要：**3–5 分钟**，他**坐着、正对镜头**，脸完整可见，单人，音频干净，25fps。
最好是他演播室节目（国旗背景那种）——那类镜头天然正对。

你给的三段我都扫过了：
- 街头辩论：分屏，60% 是 Vivek，他侧对，只有 1.8 秒安静
- 58 分钟合辑：镜头对着**提问者**，他 3/4 侧对，**0 段连续 5 秒正脸**
- 竖版 shorts：字幕烧进画面

都不行。**这一步不解决，后面全部无法开始。**

技术栈：ffmpeg、SCRFD 人脸检测、我写的 `scan_pose.py`（正脸筛选）

### 第 2 步：预处理（半天）

人脸检测 → 裁剪对齐 → 关键点 → 音频特征（HuBERT）→ 训练集。
技术栈：FeatherTalk `data_utils/process.py`（已克隆），SCRFD，PFLD，feather_hubert

### 第 3 步：训练（数小时，无人值守）

FeatherTalk 训练脚本，约 200 epoch，产出 144×144 的个人化视觉模型。
技术栈：PyTorch（MPS）。上游作者说 M 系 CPU 也能训，慢一些。

### 第 4 步：导出 + 上 ANE（半天）

PyTorch → ONNX → Core ML（mlprogram，fp16）→ **用 powermetrics 确认真跑在 ANE 上**。
风险：训出来的模型若含 ANE 不支持的算子，会静默掉回 GPU——争抢就回来了。
所以**架构定型前必须先验证**，不是训完再验。
技术栈：coremltools（已装并验证过），`bench_ane.py`

### 第 5 步：流式渲染器（1–2 天，最重的工程）

这是上游**没有**的部分——FeatherTalk 两条推理路径都是"wav 进、mp4 出"的离线模式。

要自己写：TTS 音频块 → HuBERT 特征 → 模型出嘴部 → 贴回底子帧 → 25fps 送浏览器。
关键细节（全部来自 VoxEMW 作者的血泪注释）：
- 用**虚拟时刻表**调度，不用逐帧 sleep（否则每分钟漂移 1.2–1.6%，长回复末尾口型肉眼可见落后）
- 音频**延后** 125ms 内对齐画面，永远不让声音跑在嘴前（ITU-R BT.1359）
- 打断时切待机循环，不能"一帧即停"（窗口有状态，最后几帧没有未来音频）
- 底子帧的人脸框、VAE 编码全部**离线预计算**——身份固定，这些不依赖音频

技术栈：Core ML 推理、numpy 合成、现有 orchestrator 的 WS 下行

### 第 6 步：待机状态机（已完成，复用）

就是现在页面上那套：说话/待机切换、420ms 缓冲防句间跳变、打断瞬时收嘴。
训好的模型是**插进这个框架**，不是另起炉灶。

### 第 7 步：接入 + 调优（1 天）

接进 orchestrator；处理说话→安静的过渡（上游 open issue）；调音画对齐。

## 五、诚实的时间

**素材到手后：3–5 个工作日。** 第 5 步最重。

## 六、诚实的预期

做完是什么样：**他本人的真实影像**（眼睛、眨眼、头部动作、肩膀都是真的）+ 一块
按你的话现算的嘴。视频通话尺寸下第一眼像他；经不起细看——牙齿偏软、重绘区
边缘有淡缝、说话转安静那一瞬间最容易破功。

那个几百人的盲测说：对练习型对手，**响应速度与体验相关 0.697，画质只有 0.473**。
一个嘴稍软但你一插话就停的，胜过一个更锐但慢 300ms 的。

## 七、另一条路（要说清楚）

如果"尽快看到效果"比"完全本地"更重要：**租一张 4090**（AutoDL 之类），
把 VoxEMW 原样跑起来。那正是 B 站作者的做法。大脑、音色、人设都可以复用我们的。
代价：不本地、按小时付费、要架隧道。
